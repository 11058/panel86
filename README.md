# Панель 86

Прошивка настенной панели управления умным домом на **ESP32-P4** в стандартном
подрозетнике 86 × 86 мм. Плата — Waveshare ESP32-P4-86-Panel-ETH-2RO
(4″ IPS 720 × 720, MIPI-DSI, Ethernet, 2 реле, RS485, микрофоны и динамик).

**Главная идея:** ESPHome берёт на себя фундамент — сеть, провижининг, OTA,
протокол с Home Assistant, драйверы. Раскладка интерфейса при этом становится
**данными**: JSON в LittleFS, который интерпретируется на лету. Переставить
карточку — это правка в браузере, а не пересборка прошивки.

Полный концепт с обоснованием: [артефакт «Панель 86»](https://claude.ai/code/artifact/c02acc31-80d4-46c3-a774-5194107510ea).

## Зачем ещё одна прошивка

Для этой платы уже есть шесть попыток, и все упираются в одно и то же.

| Проект | Фундамент | Настройка UI |
|---|---|---|
| `alaltitov/…-86-Panel-ETH-2RO` | свой | нет, всё в коде |
| DarkForge UI | свой | веб-UI, но исходники закрыты |
| BETTA HA Panel | свой | drag & drop, разработка заглохла |
| GalusPeres/HomeTiles | свой | веб-админка, но нужен MQTT-мост |
| openHASP | свой | JSONL вручную, координаты LVGL-объектов |
| `chrisdunnname/esphome-…-lvgl` | **ESPHome** | **9 888 строк YAML и пересборка** |

Первые пять переписывают шесть чужих слоёв и на UI ресурса не оставляют.
Шестой берёт готовый фундамент, но настройка в нём — фиксированные слоты
`lights1..6` в почти десятитысячестрочном YAML.

Свободна ровно одна клетка: **чужой фундамент + настройка в рантайме**.

## Что уже известно точно

Замерено на рабочем Home Assistant 2026.8.3 (1271 сущность), см.
[`docs/02-ha-survey.md`](docs/02-ha-survey.md):

- `subscribe_entities` **с фильтром по `entity_ids` работает**: 4 КиБ на комнату
  против 319 КиБ на всю установку — разница в 80 раз.
- Обновления приходят **push**, в момент изменения: 46 событий за 45 секунд
  по подписке на пять активных датчиков. При этом комната, где ничего
  не происходит, не порождает трафика вовсе. Нагрузка пропорциональна экрану,
  а не размеру дома.
- Датчики шумят: напряжение обновляется раз в 1,6 с, 88 % изменений — меньше
  0,5 В. В формате раскладки поэтому есть `deadband` и `throttle`, включённые
  по умолчанию.
- **92 % сущностей не привязаны к комнатам.** Это блокер для room-first
  интерфейса, и чинится он в Home Assistant, а не в прошивке.
- На живой плате: **84–95 к/с** при 720×720, 16 бит, буфер 25 %, без ускорения
  PPA. Образ 1,0 МБ — 6 % флеша. Кириллица стоит ~90 КБ и требует своих
  шрифтов: встроенные `montserrat_*` дают квадратики.
- **Привязка сущностей HA в рантайме работает через нативный API** — без
  токена и второго соединения. Цена — переподключение к API, измерено
  **87 мс** от разрыва до первого состояния.

## Структура

```
firmware/
  panel86-p0.yaml           фаза P0: приборы и бенчмарк, своего кода нет
  packages/board.yaml       железо: пины, дисплей, тач, подсветка, реле
  packages/net-ethernet.yaml  профиль сети по умолчанию
  packages/net-wifi.yaml      Wi-Fi через C6, резерв
schema/layout-v1.schema.json  формат раскладки
examples/                     раскладки на реальных сущностях
docs/01-p0-bringup.md         протокол замеров P0
docs/02-ha-survey.md          что показал живой HA
docs/adr/                     архитектурные решения
tools/ha_probe.py             инструмент разведки HA
```

## Начать

```bash
cp firmware/secrets.yaml.example firmware/secrets.yaml   # заполнить
esphome config firmware/panel86-p0.yaml
```

Дальше по шагам: [`docs/01-p0-bringup.md`](docs/01-p0-bringup.md).

### Разведка своего Home Assistant

```bash
export HA_WS="wss://ваш-хост/api/websocket"
export HA_TOKEN="долгоживущий токен"     # НЕ коммитить
python3 tools/ha_probe.py
```

На macOS со сборкой с python.org проверка сертификатов падает — выгрузить
системное хранилище:

```bash
security find-certificate -a -p \
  /System/Library/Keychains/SystemRootCertificates.keychain > roots.pem
export HA_CA=roots.pem
```

## Дорожная карта

| | Фаза | Срок |
|---|---|---|
| P0 | Живое железо и цифры | ~1 неделя |
| P1 | Один хороший экран на статичном LVGL | ~2 недели |
| P2 | Спайк: привязка сущностей в рантайме | 3–5 дней |
| P3 | UI-VM: JSON → LVGL, каталог карточек | 4–6 недель |
| P4 | Веб-редактор, превью на LVGL в WebAssembly | ~4 недели |
| P5 | Голос, presence, камеры, Modbus | по мере сил |

## Лицензия

Не выбрана — решение за автором. Открыть стоит с первого коммита, а не
«когда доделаю»: закрытость DarkForge ровно та причина, по которой пишется
эта прошивка вместо патча к ней. Выбирать из совместимых с ESPHome, чтобы
части внешнего компонента можно было отдать в апстрим.
