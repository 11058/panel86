# P0 — «Живое железо и цифры»

Цель фазы — не интерфейс, а **числа**. Пока их нет, любое архитектурное
решение ниже по стеку принимается вслепую.

Своего кода в этой фазе нет и быть не должно: только стоковый ESPHome.

---

## Порядок работ

### 1. Проверить, что конфиг вообще собирается

```bash
cp firmware/secrets.yaml.example firmware/secrets.yaml   # заполнить
esphome config  firmware/panel86-p0.yaml                 # синтаксис и пины
esphome compile firmware/panel86-p0.yaml                 # реальная сборка
```

> **Конфиг ни разу не компилировался.** Он собран из проверенного рабочего
> конфига `chrisdunnname/esphome-p4-86-panel-eth-2ro-lvgl` и wiki Waveshare,
> но имена опций и синтаксис LVGL могли разойтись с вашей версией ESPHome.
> Минимальная версия — 2026.7.0. Первое расхождение чините здесь, а не на плате.

### 2. Прошить по USB и увидеть картинку

```bash
esphome run firmware/panel86-p0.yaml --device /dev/cu.usbmodem*
```

Признаки успеха по возрастанию: пошёл лог по UART → зажглась подсветка →
появился текст → реагирует тач.

Если экран чёрный, а лог идёт — почти наверняка `esp_ldo` (канал 3, 2.5 В).
Без него не поднимается PHY MIPI-DSI.

### 3. Снять базовые числа

Все приборы уже в конфиге и выезжают в HA как diagnostic-сущности:
свободная куча, свободный PSRAM, время цикла, температура SoC, время работы.

Кнопка «Запустить бенчмарк» гоняет 120 полных перерисовок экрана и печатает
в лог кадры в секунду. Число грубое — важна не абсолютная величина, а
**сравнение между настройками**.

### 4. Прогнать матрицу настроек

Меняем по одному параметру и записываем в таблицу ниже.

| # | `color_depth` | Доля буфера | Ускорение PPA | к/с | Время цикла, мс | Свободный PSRAM |
|---|---|---|---|---|---|---|
| 1 | 16 | 25 % | нет | | | |
| 2 | 16 | 25 % | да | | | |
| 3 | 16 | 50 % | да | | | |
| 4 | 16 | 100 % | да | | | |
| 5 | 24 | 25 % | да | | | |
| 6 | 24 | 50 % | да | | | |

Полный кадр 720×720: **1,04 МиБ** при 16 битах, **1,55 МиБ** при 24.
Двойная буферизация в 16 битах — около 2 МиБ из 32 МиБ PSRAM. Места хватает
с запасом; узкое место — не объём, а полоса пропускания PSRAM.

> Имена опций ускорения (`use_ppa` и доля буфера) уточнить по документации
> вашей версии: они появились недавно, в рамках работы над производительностью
> LVGL на P4 (esphome/esphome#16873). В `board.yaml` они намеренно не выставлены.

### 5. Проверить сеть — оба профиля

Ethernet (профиль по умолчанию):

```yaml
packages:
  net: !include packages/net-ethernet.yaml
```

Wi-Fi через C6 — **отдельная сборка, отдельные сутки наблюдения**:

```yaml
packages:
  net: !include packages/net-wifi.yaml
```

Что искать в логе: `Dropping packet(s) from stream`, `Failed to push data to
rx queue`, повторные `Association Leave`. Это известная проблема
(esphome/esphome#10956, ровно эта плата). Если воспроизводится — Ethernet
становится не «рекомендацией», а требованием.

### 6. Проверить локальный фолбэк

Кнопка «Реле 1» на экране переключает реле напрямую, минуя Home Assistant.

**Тест:** выдернуть сетевой кабель → нажать кнопку на экране → реле должно
щёлкнуть. Если не щёлкает — это блокер, а не косметика: выключатель, который
перестаёт работать при падении сервера, продавать нельзя.

### 7. Тепловой тест — в настоящей коробке

Собрать в подрозетник, закрыть, дать поработать **два часа** на рабочей
яркости. Снять температуру SoC в начале и в конце.

| | Температура SoC |
|---|---|
| Через 1 мин после загрузки | |
| Через 30 мин | |
| Через 120 мин | |
| Через 120 мин при подсветке 20 % | |

Разница между последними двумя строками — это цена яркости, и она же
обоснование того, чтобы гасить экран при отсутствии людей.

В `board.yaml` подсветка ограничена сверху `max_power: 0.8` именно поэтому.

### 8. Физика

- [ ] Влезает ли RJ45 в вашу коробку? Нужно **≥ 35 мм**, при 33–35 мм —
      коннектор с коротким корпусом.
- [ ] Замерить реальную глубину имеющихся подрозетников.
- [ ] Если планируется профиль B (панель вместо выключателя) — где физически
      разместится модуль AC/DC? Скорее всего нужна коробка ≥ 60 мм.

## Результаты первого включения — 4 сентября 2026

Плата: ESP32-P4 **rev v1.3**, 2 ядра + LP, **360 МГц** (esptool рапортует
«400MHz» как признак семейства, реальная частота из лога — 360),
флеш 32 МБ определился автоматически, MAC `E8:F6:0A:E0:F1:E4`.
ESPHome 2026.8.2, ESP-IDF v5.5.5.

### Что заработало сразу

- Дисплей 720×720 по MIPI-DSI, пресет `WAVESHARE-P4-86-PANEL` — без бубна.
- Тач GT911.
- LVGL, кнопки, реакция на касание.

### Производительность — риск снят

| Прогон | Полных перерисовок | Время | к/с |
|---|---|---|---|
| 1 | 120 | 1393 мс | **86,1** |
| 2 | 120 | 1265 мс | **94,9** |
| 3 (после смены шрифта) | 120 | 1429 мс | **84,0** |

Настройки по умолчанию: `color_depth: 16`, `buffer_size: 25%`, **без** PPA.

Главный технический риск концепта — потянет ли LVGL 720×720 — закрыт
с запасом почти втрое. Ускорение PPA и подбор доли буфера пока не нужны:
их стоит трогать, только когда появится по-настоящему тяжёлый интерфейс.

**Оговорка честности:** бенчмарк гоняет полную инвалидацию простой страницы
(пара меток и две кнопки), а не сложный UI со списками и градиентами.
Число опорное, не потолочное. Матрицу настроек имеет смысл прогнать заново
на реальном экране комнаты в P1.

### Занятые ресурсы

| | |
|---|---|
| Образ | 1 009 762 Б (**6,1 %** флеша) |
| DIRAM | 97 376 Б (**16,9 %** из 576 464) |
| PSRAM под код и данные | ~843 КБ из 128 МБ адресуемых |

Образ вырос с 917 КБ до 1010 КБ после добавления кириллических шрифтов —
93 КБ это цена двух начертаний Roboto с `GF_Cyrillic_Core` в `bpp: 4`.

### Что сломалось и как починено

**1. GPIO35 — это EMAC_TXD1.** Боковая кнопка на GPIO35 конфликтует
с Ethernet. Поймано `esphome config` до прошивки. Кнопка вынесена
в `packages/side-button.yaml`, совместимый только с профилем Wi-Fi.
Это же объясняет, почему в референсном конфиге Ethernet закомментирован.

**2. Весь русский текст выводился квадратиками.** Встроенные шрифты
`montserrat_*` содержат только латиницу. Поймано глазами на живой плате —
валидация такое пропускает.

Лечение: свои шрифты с `glyphsets: [GF_Latin_Core, GF_Cyrillic_Core]`
(241 кириллический глиф) плюс `default_font` на уровне `lvgl:`, иначе
подписи внутри кнопок наследуют латинский шрифт LVGL и остаются
квадратиками, даже когда метки уже починены.

**Вывод на будущее:** в UI-VM набор глифов придётся считать от содержимого
раскладки. Названия комнат и сущностей приходят из Home Assistant в рантайме,
то есть заранее неизвестны — значит шрифт должен покрывать кириллицу целиком,
и эти ~90 КБ надо сразу заложить в бюджет флеша.

**3. `/` в имени сенсора.** «Бенчмарк, к/с» — с ESPHome 2027.7 станет ошибкой,
переименовано.

### Ethernet — пока не проверен

Кабель в панель не подключён, поэтому `Connecting failed; reconnecting`
каждые 15 с — ожидаемое поведение, а не дефект.

Но два факта записаны:

- `Setup ethernet took 4352ms`. Без кабеля это **4,3 секунды впустую**
  при каждой загрузке. Если панель штатно живёт на Wi-Fi — профиль Ethernet
  надо убирать, а не оставлять «на всякий случай».
- **Пины IP101 всё ещё не подтверждены.** Они взяты из закомментированного
  блока референсного конфига, то есть не проверялись никем. Первое же
  подключение кабеля их и проверит.

### Осталось в P0

- [ ] Ethernet с кабелем: подтвердить пины IP101 и сутки без переподключений
- [ ] Локальный фолбэк реле при выдернутом кабеле
- [ ] Тепловой тест два часа в закрытом подрозетнике
- [ ] Матрица настроек производительности (пока не нужна — запас большой)
- [ ] Wi-Fi через C6: воспроизводится ли esphome/esphome#10956

## Второй день, 5 сентября 2026: сеть и настройка с экрана

### Wi-Fi заработал, оба канала уживаются

Панель на `10.1.20.115`, сигнал −63 дБм, канал 8, `Default interface: sta`.

ESPHome **не даёт** объявить `wifi:` и `ethernet:` вместе — если только оба
не перечислены в блоке приоритетов:

```yaml
network:
  priority: [wifi, ethernet]
```

Первый в списке держит маршрут по умолчанию. Это лучше двух отдельных сборок:
воткнули кабель — панель им пользуется, выдернули — ушла на Wi-Fi.

**OTA работает: 6,3 секунды** на образ в 1,5 МБ. USB больше не нужен,
кроме как для спасения (см. ниже — понадобилось).

### Основная сеть оказалась скрытой

В логе: `No matching network found` → `Retry phase: RETRY_HIDDEN` →
`Hidden candidate 'SRVPRMiot'`.

Скрытая сеть **не появляется в результатах сканирования в принципе**. Это
сломало первоначальный замысел экрана настройки «выбери сеть из списка»:
подключить панель к основной сети дома через него было бы нельзя.

Поэтому поле имени сети сделано редактируемым, а на экране списка есть
кнопка «Скрытая сеть — ввести имя вручную». Требование к любой будущей
настройке Wi-Fi: **ручной ввод имени обязателен, список — только удобство.**

### Две LVGL-клавиатуры вешают прошивку

Добавление второго экрана с собственной клавиатурой (первая — для пароля,
вторая — для имени сети) привело к циклу перезагрузок:

```
E (9927) task_wdt: Task watchdog got triggered ... loopTask (CPU 1)
[E][safe_mode:213]: Boot loop detected
```

Сторожевой таймер убивал главный цикл примерно через 9,9 с после старта,
каждую загрузку. Панель поднималась только по USB.

Лечение и одновременно улучшение: **одна клавиатура на два поля**. Имя сети
и пароль теперь на одном экране, цель ввода переключается касанием поля
через `lv_keyboard_set_textarea()`. После переделки прошивка загружается
нормально.

**Честная оговорка:** причина не изолирована A/B-тестом — вывод сделан
по тому, что боевой цикл появился ровно с добавлением второй клавиатуры
и исчез с её удалением. Если в P3 понадобится несколько клавиатур,
разбираться придётся всерьёз.

**Вывод для UI-VM:** тяжёлые LVGL-виджеты нельзя плодить по экземпляру
на страницу. Каталог карточек должен переиспользовать один экземпляр
клавиатуры и других крупных виджетов, создавая их лениво.

### Особенности API ESPHome, стоившие времени

Виджеты LVGL отображаются в C++ по-разному, и это не написано в документации:

| Виджет | Что возвращает `id(...)` | Как обращаться |
|---|---|---|
| `textarea` | `lv_obj_t *` | `id(ta)` напрямую |
| `roller` | `LvRollerType *` | `id(r)->obj`, либо `id(r)->get_selected_index()` |
| `keyboard` | `LvKeyboardType *` | `id(kb)->obj` |

Определять по классу в `lvgl_esphome.h`: обёртки наследуют `LvCompound`
с публичным полем `obj`.

### PPA отключён в апстриме

В ESPHome 2026.8.2: `df.add_define("LV_USE_PPA", "0")` с комментарием
«disable use of PPA for fills until upstream bugs fixed». Опции `use_ppa`
не существует.

Значит, измеренные 84–95 к/с получены **вообще без аппаратного ускорения**,
и запас больше, чем казалось. Матрица «с PPA / без» отменяется до тех пор,
пока апстрим его не включит обратно.

### Разделы флеша: под LittleFS места нет

```
app0   0x00010000  0x00FC0000     nvs   0x01F90000  0x00070000
app1   0x00FD0000  0x00FC0000
```

Две OTA-области по 16,5 МБ съедают все 32 МБ. **Раздела под данные нет.**
Для P3, где раскладка должна лежать в LittleFS, понадобится своя таблица
разделов: две области по 16,5 МБ избыточны для образа в 1,5 МБ.
Разумно: app0/app1 по 4 МБ, остальное под данные.

### Что снято и что осталось

Снято: производительность, Wi-Fi, OTA, шрифты, кириллица.

Осталось: Ethernet с кабелем (пины IP101 всё ещё не подтверждены),
локальный фолбэк реле, тепловой тест, сутки Wi-Fi под наблюдением
на предмет esphome/esphome#10956.

### Три бага экрана настройки, найденные глазами

Ни один не ловится ни валидацией, ни компиляцией — только живой панелью.

**1. Символы клавиатуры выводились квадратиками.** Shift, Backspace, Enter
и стрелки LVGL рисует символами из приватной области Unicode. В шрифтах
с `GF_Latin_Core + GF_Cyrillic_Core` их нет. Лечение: клавиатуре задан
встроенный `montserrat_20`, где эти символы есть, — кириллица на латинской
раскладке не нужна.

**2. Панель стартовала с экрана настройки, хотя сеть была настроена.**
Страницы из пакетов попадают в список раньше страниц основного конфига,
и стартовой оказывалась `page_wifi_list`. Проверяется по собранному конфигу:
`page_wifi_list` в строке 377, `page_p0` — в 567. Опции «начальная страница»
в ESPHome нет.

Лечение — и заодно нужное поведение:

```yaml
on_boot:
  - priority: -100
    then:
      - if:
          condition:
            lambda: 'return wifi::global_wifi_component->has_sta();'
          then: [ lvgl.page.show: page_p0 ]
          else: [ lvgl.page.show: page_wifi_list ]
```

`has_sta()` истинно, если сеть задана хоть откуда-то — зашита в прошивке
или поднята из NVS. Ложно — панель включили впервые, показываем настройку.

**3. Из экрана настройки нельзя было выйти.** Кнопки возврата не было.
Добавлена.

### Сохранение в NVS: как проверить честно

Пока имя сети зашито в `secrets.yaml`, отличить «панель взяла сеть из NVS»
от «взяла из прошивки» **невозможно** — подключение к нужной сети ничего
не доказывает.

Поэтому добавлен профиль `packages/net-wifi-provision.yaml`: без `ssid`
и `password`, только точка доступа. С ним `has_sta()` ложно, панель сама
открывает настройку, и подключение возможно только через введённое руками.
Отдельный конфиг — `firmware/panel86-provision.yaml`.

Это и боевой сценарий первого включения, и единственная честная проверка
записи в ПЗУ.

## Критерий выхода из P0

Фаза закрыта, когда:

1. Таблица настроек заполнена и выбрана рабочая комбинация.
2. Прокрутка списка субъективно плавная (проверяется съёмкой на 120 к/с
   и подсчётом кадров, а не на глаз).
3. Ethernet держит соединение сутки без переподключений.
4. Реле щёлкает при выдернутом кабеле.
5. Температура через два часа в закрытой коробке известна.

Если пункты 1–2 не вытягиваются ни при каких настройках — это разговор
об изменении концепта (меньше анимаций, 16 бит, частичные буферы), и лучше
его провести сейчас, а не через полгода.
